# 11 · Idiomas (i18n)

O Folio é bilíngue: **português do Brasil** e **inglês**. Por padrão, a interface segue o idioma do sistema; o usuário pode fixar um dos dois.

## Idioma ativo

O usuário escolhe entre **Seguir o sistema** (padrão), **Português** e **English**.

- **Seguir o sistema:** `locale()` do `@tauri-apps/plugin-os`, lido na inicialização. Não usa `navigator.language`, que no WebKitGTK nem sempre reflete o `LANG` do sistema.

  | Idioma do sistema | Idioma do Folio |
  |---|---|
  | `pt` em qualquer variante (`pt-BR`, `pt-PT`...) | Português do Brasil |
  | Qualquer outro | Inglês |

- **Persistência:** a escolha fica no banco global, na preferência `language` (`"system"`, `"pt-BR"` ou `"en"`; `specs/02-persistencia.md`). Valor ausente ou desconhecido vale `"system"`.
- **Troca ao vivo:** mudar o idioma atualiza a interface inteira na hora, sem recarregar.
- O atributo `lang` do `<html>` acompanha o idioma ativo, para hifenização e leitores de tela.

## Seletor de idioma

No rodapé da sidebar, à esquerda do seletor de tema (`03-sidebar.md`, 3.4):

- **Botão:** mesmo grupo visual do seletor de tema (fundo `--surf-2`, borda 1px `--line-6`, raio 14, padding 2), com um único segmento de 24×20, raio 10, ícone Lucide `languages` 13px `--tx-10`; hover e aberto: fundo `--surf-4`, ícone `--nav-accent`. `title`: "Idioma" / "Language".
- **Menu:** o dropdown de `06-components.md`, abrindo **para cima** (o rodapé fica no fim da janela), alinhado à direita do botão. Fecha com clique fora, Esc ou ao escolher.
- **Itens:** "Seguir o sistema" / "Follow system", "Português", "English". Os nomes dos idiomas aparecem sempre na própria língua. O item ativo leva o ícone Lucide `check` 13px `--nav-accent` à direita.

## O que é traduzido

- **Todo texto da interface:** rótulos, botões, placeholders, `title`, `aria-label`, toasts, estados vazios, diálogos e mensagens de erro.
- **Formatação de números, tamanhos e datas**, pelo `Intl` com o idioma ativo:

| Dado | Português | Inglês | API |
|---|---|---|---|
| Tamanho | `4,1 MB` | `4.1 MB` | `Intl.NumberFormat` (1 casa decimal) |
| Contagem | `1.284 arquivos` | `1,284 files` | `Intl.NumberFormat` + `Intl.PluralRules` |
| Tempo relativo | `há 2 d` | `2d ago` | `Intl.RelativeTimeFormat` com `style: "narrow"` |
| Data | `18 mar, 21:30` | `Mar 18, 21:30` | `Intl.DateTimeFormat` |

O formato em português é o de `08-data.md`. Se o `Intl` do WebKitGTK não produzir exatamente o texto do design, o formatador ajusta o resultado, e um teste fixa a saída esperada nos dois idiomas.

## O que não é traduzido

- **Nomes de arquivos, pastas e projetos:** são os do disco.
- **Conteúdo e metadados dos documentos.**
- **Nomes de formato** (PDF, DOCX, MD, TXT) e o nome do app.
- **Caminhos.** A pasta de documentos do sistema já vem no idioma do sistema (`~/Documentos` ou `~/Documents`, `specs/03-workspace.md`).

## O backend não devolve texto

O `folio-core` e os commands do Tauri **nunca devolvem texto para o usuário**. Erros e avisos cruzam a ponte como dados:

- Cada erro é uma variante de um enum Rust exportado pelo ts-rs, serializado com tag (`{ "kind": "AlreadyExists", "name": "Trabalho.docx" }`), com os dados de que a mensagem precisa como campos.
- O frontend tem uma mensagem por variante em cada idioma (ver "Biblioteca"): um erro novo no Rust sem mensagem quebra o `tsc -b`.
- Erro de I/O do sistema operacional chega com o tipo genérico e o caminho; a mensagem é genérica ("Não foi possível acessar `<caminho>`") e o detalhe técnico vai para o log, não para a tela.

As mensagens escritas nas specs de backend (`specs/`) são o texto em português de cada erro; o inglês é escrito no dicionário, junto com a implementação.

## Biblioteca

**`i18next` + `react-i18next`.** O detector de idioma do navegador (`i18next-browser-languagedetector`) não é usado: o idioma vem da preferência e do `plugin-os`.

```text
src/lib/i18n/
├── pt.ts           # recursos em português: a forma de referência
├── en.ts           # mesma forma, verificada por tipo
├── format.ts       # tamanhos, contagens, datas e tempo relativo
├── language.ts     # preferência e idioma do sistema → idioma ativo
├── systemLocale.ts # locale() do plugin-os
├── errors.ts       # variante de erro do backend → chave de mensagem
├── useFormat.ts    # formatadores ligados ao idioma ativo
└── index.ts        # inicialização do i18next e tipagem
```

- **Chaves tipadas:** `CustomTypeOptions` do i18next declara `pt` como recurso de referência, e `t("chave.inexistente")` quebra o `tsc -b`.
- **Completude:** `en.ts` declara `satisfies Resources`, onde `Resources` é a forma do `pt.ts` com valores `string`. Chave faltando ou sobrando em qualquer idioma quebra o `tsc -b`.
- Chaves agrupadas por feature em inglês, como todo identificador (`sidebar.favorites.empty`, `errors.alreadyExists`).
- **Interpolação** do i18next (`"Já existe um item chamado {{name}}"`), com `escapeValue: false` porque o React já escapa. Nada de concatenar pedaços de frase no componente.
- **Plural** pelos sufixos do i18next (`_one`, `_other`), que usam `Intl.PluralRules`. Nunca `n === 1 ? ... : ...` no componente.
- **Erros do backend:** `errors.ts` é um `Record` do tipo da variante para a chave da mensagem. Uma variante nova no Rust sem entrada no `Record` quebra o `tsc -b`.
- Os formatadores de `format.ts` usam o `Intl` com o idioma ativo do i18next.

## Regras para o código

- **Nenhum texto fixo em componente.** Todo texto visível vem do `t()` do `react-i18next`.
- Os testes de componente rodam em português e verificam o texto do dicionário, não uma string repetida no teste.
- Um teste percorre os dois dicionários e garante que nenhum valor está vazio.

## Critérios de aceite

- [x] Com "Seguir o sistema", num sistema em português toda a interface aparece em português; em qualquer outro idioma, em inglês.
- [x] Escolher um idioma no seletor muda a interface na hora e a escolha persiste entre aberturas.
- [x] Nenhum texto visível vem de string fixa em componente.
- [x] Remover uma chave do `en.ts` ou do `pt.ts` quebra o `just check`.
- [x] Toda variante de erro do backend tem mensagem nos dois idiomas; uma variante nova sem mensagem quebra o `just check`.
- [x] Tamanhos, contagens e datas seguem a tabela de formatação nos dois idiomas.
- [x] O `lang` do `<html>` é `pt-BR` ou `en`, conforme o idioma ativo.
